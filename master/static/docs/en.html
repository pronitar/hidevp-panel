About the panel

HideVP Panel runs your own VPN service on Xray-core. One master panel manages everything: servers, VPN connections, users, the Telegram bot, payments and updates. Each VPN server runs a work panel (agent) that receives settings from the master and runs Xray.

PartWhereWhat it does
Master panelOne server (can be in Russia)Admin panel, user site, subscriptions, Telegram bot, payments, backups
Work panelEvery VPN serverXray, connections, traffic and device accounting, server checks
hidevp consoleAny server with the panelInstall, update, rollback, domain, logs, access recovery

A user gets one subscription link with all enabled connections. It works in Happ, INCY and other Xray clients. Disabling, renewing or limiting a user takes effect on all servers within about a minute, without restarting Xray.

Requirements

  • A VPS with Ubuntu 22.04/24.04 or Debian 11/12 and root SSH access. 1 CPU and 1 GB RAM are enough.
  • Servers need access to github.com for Xray-core and updates.
  • A Telegram bot (created with @BotFather).
  • Preferably a domain with an A record pointing to the master server. Without a domain the admin panel runs on http://IP:port without encryption.

Installation

Run one command on each server to open the installer menu:

bash <(curl -fsSL https://github.com/pronitar/hidevp-panel/releases/latest/download/install.sh)

Without GitHub access: download hidevp-panel-<version>.zip from Releases, upload it to /root and run cd /root && unzip -o hidevp-panel-*.zip && bash hidevp-panel/hidevp.sh.

Master panel

  1. Choose "Install the master panel" in the menu.
  2. Domain. Enter a domain whose A record already points to the server. With nginx running, the panel adds a separate site and a certbot certificate without touching other sites; without nginx, Caddy is installed. Press Enter to install without a domain on http://IP:random_port. You can add a domain later: hidevp → "Domain and certificate".
  3. Stub site. The installer asks whether to enable it. Recommended: the home page shows an ordinary website and user sign-in moves to a secret address (see "Server camouflage").
  4. At the end you get the admin URL (with a random secret path), login and password — save them.

Work panel

  1. Choose "Install the work panel". Xray-core and the agent are installed and BBR is enabled.
  2. At the end you get a table of free ports and the NODE-… key.
  3. In the admin panel: Servers → Connect server and paste the key. The management port is then closed to everyone except the master panel's IP.

Ports

ServerPortPurpose
master80, 443With a domain: site, admin panel, subscriptions

Ports are opened in ufw automatically. If your hoster has an external firewall, open the ports there too.

hidevp console

hidevp opens a menu: sign-in details, login and password, domain and certificate, node key, Xray (restart, reinstall, config test, "Open the work panel API"), logs, update, rollback, reinstall and removal, language.

hidevp-panel info               # admin URL and login
hidevp-panel reset-admin        # new login and password
hidevp-panel set-stub on|off    # stub site
hidevp-node key | rotate        # node key
journalctl -u hidevp-panel -f   # master log
journalctl -u hidevp-node -f    # work panel log
journalctl -u xray -f           # Xray log

First setup

  1. Settings — service name, public URL (with a domain: https://domain), support contact, default limits. Change the admin password.
  2. Servers → Connect server — the NODE-… key of each node.
  3. VPN → Create — server, protocol, transport, camouflage site. The port is filled in automatically.
  4. Telegram bot — token, admin linking, a route via a foreign server if needed.
  5. Plans & payments — periods, prices, payment methods.
  6. Users → Create — a test user; open their subscription link in Happ.
  7. Servers → Check on every server — all items should be green.
  8. Backups — enable automatic backups.

Servers

The page opens instantly; each server's state loads separately. A card shows the country flag, address, work panel and Xray versions, CPU, memory and disk load, and the number of VPNs.

  • Check — diagnostics: Xray running, ports listening and reachable, firewall, camouflage site, own site and its certificate, internet access through each connection, clock accuracy. Red items come with a hint.
  • SOCKS5 — a login/password proxy for the administrator only: a socks5:// link, an app import link and a Telegram proxy link. It is never added to user subscriptions. Traffic is not encrypted — use it for your own tasks.
  • Edit — name, address, country. Delete removes the server from the panel (the server itself is untouched).

The work panel management port is closed to everyone except the master panel's IP by default. If the master panel uses a domain, after its IP changes just update the A record: servers check the domain every 3 minutes and open the port for the new address by themselves (work panel 1.7.1). If the panel uses an IP, on each server run: hidevp → Xray → "Open the work panel API".

If a server's own IP changes (including the server that runs the master panel), work panel 1.7.2 notices it within 5 minutes and reports it to the master panel. The panel checks that the server answers at the new address, updates it, pushes the settings and notifies administrators. Subscription links update when users refresh the subscription in the app. This needs a domain or an unchanged IP in the panel's public address.

VPN connections and encryption

A connection is a protocol, port and camouflage on a specific server. A server can have several; all enabled connections appear in the subscription in "Order" order.

Protocols

Form fields

  • Port — 443 is best; if taken, 8443 or 2053. The panel checks the port is free and reachable and suggests free ones.
  • Camouflage site (SNI) — foreign sites, Russian sites (for servers in Russia), own site (self-steal) or another site.
  • TLS fingerprint — Chrome by default.
  • Internet exit — from this server or via a connection on another server (cascade).
  • Regenerate keys — new Reality keys and passwords; users need to refresh the subscription.

Camouflage against blocking

The most reliable setup is several different connections in the subscription plus auto selection: when the carrier blocks one, the app moves to another.

How it's blockedWhat helps

Own site (self-steal)

  1. Create an A record for a subdomain (e.g. fr.your-domain.com) pointing to the server IP, without Cloudflare proxying.
  2. Port 80 on the server must be free or used by the master panel's nginx.
  3. In the VPN, choose the SNI "Own site on this server" and enter the domain. The panel installs Caddy, gets a Let's Encrypt certificate and shows a simple page (edit it in /opt/hidevp-panel/node/data/site/<domain>/index.html).
  4. After 1–2 minutes, "Check" → "Own site … works" should be green.

Cascade

The phone connects to a server in Russia, which forwards traffic to a connection abroad. For the carrier it's a domestic connection. Requires work panel 1.3.0+ on both servers and a VPS at a large Russian hoster. In the VPN on the Russian server, choose a Russian SNI and "Internet exit → Via …". The subscription shows the exit country's flag.

Auto selection and fragmentation

Checkboxes at the top of the VPN page. Auto selection adds "⚡ Auto" in Happ and INCY: the app tests connections (except Hysteria2) and uses the fastest working one. TLS fragmentation splits the first packet with the site name. For Happ and INCY the subscription is then served as Xray JSON — the app's own routing rules don't apply.

Server camouflage

Settings → "Server camouflage":

  • Stub site — the domain's home page shows an ordinary website (personal page, under construction, studio, file storage, speed test, blog, maintenance or custom HTML). Users sign in at a secret cabinet address that the bot sends automatically. Unknown addresses answer like plain nginx.
  • Scanners — the panel notices IPs that request 8 or more non-existent addresses within 10 minutes. They can be blocked for 7 days (404 on the home page, in the cabinet and at sign-in) and summarized daily in Telegram. The admin panel, subscriptions and personal pages still work for blocked IPs; the administrator's IP is never blocked.
  • Hide the work panels' API — the management port on servers is open only to the master panel's IP.

Ready-made setups for different situations are in "Recommended setups".

Users

  • Create — name, period in months or unlimited, traffic limit (GB), device limit, torrent blocking.
  • Statuses: active, expired, traffic exceeded, suspended (device limit exceeded, 10 minutes), disabled manually.
  • Device limit counts different IPs in recent minutes. Suspension happens only if the excess lasts over 2.5 minutes — switching Wi-Fi ↔ mobile doesn't trigger it.
  • Actions: renew, reset traffic, regenerate links (the old subscription stops working), message in Telegram, payment history.
  • User page — a personal /u/… link: status, expiry, traffic, QR code, "Add to Happ / INCY" buttons, renewal.
  • Subscription link /sub/… — one for all connections; Happ, INCY, v2rayNG, Hiddify, NekoBox and other Xray clients.
  • Site sign-in — by phone number: the code arrives in the bot. The number is linked when the user shares it with the bot.

Telegram bot

  1. Create a bot with @BotFather (/newbot) and copy the token.
  2. Admin panel → Telegram bot → paste the token → "Save".
  3. Connection to Telegram. If the master is in Russia and Telegram is unreachable, choose "Via a connected server" and a foreign node, or "Via proxy" (socks5:// — the SOCKS5 of one of your servers works).
  4. Link my Telegram — get a code and send it to the bot: you become a bot admin and receive notifications about payments, transfers, new users and errors. The code is time-limited and is reset after 5 wrong attempts.

The bot for users

  • /start — the bot creates the user; the subscription starts after a payment, a promo code or renewal by the administrator. To sign in on the site, the user shares their phone number with the bot.
  • Menu — my subscription (status, expiry, traffic, link, QR), buy or renew, regenerate links, instructions, support, language.
  • Buttons and texts — in the admin panel you can enable and disable menu buttons, reorder them, edit texts and add your own link buttons.
  • Clean chat — the bot deletes old menu messages so history doesn't pile up.
  • Notifications — 3 days before expiry and at expiry; device limit exceeded.

Plans and payments

  • Plans — periods from 1 to 24 months, each with prices in Stars and in a currency (₽, $, €, ₸, ₴, Br).
  • Telegram Stars — work right away, no setup.
  • Card (Telegram provider) — connect a payment provider in @BotFather → Payments and paste the "Provider token".
  • CryptoBot — in @CryptoBot: Crypto Pay → Create app → copy the token. Payments are checked every 20 seconds.
  • YooKassa — cards, SBP and SberPay on the YooKassa page. Requires a YooKassa contract; the shopId and secret key are in your account: Integration → API keys. Receipts under 54-FZ can be sent to the user's linked phone or to the e-mail from the settings. Payment is checked every 20 seconds.
  • Platega — SBP and cards. The Merchant ID and secret key are in your Platega account. You can preset the method or let the buyer choose.
  • YooMoney — a transfer to your wallet, no business registration or contract. Enter the wallet number, then on yoomoney.ru/transfer/myservices/http-notification paste the notification URL from the admin panel and copy the secret to the panel. The subscription renews as soon as the transfer notification arrives. The panel needs a public address.
  • YooKassa, Platega and YooMoney accept rubles only — choose RUB.
  • Transfers — enter card or SBP details. The user gets a unique code for the payment comment and taps "I have paid"; you check the incoming payment and confirm in the bot or the admin panel.
  • Paying on the site — the user page offers the same plans and methods.

The price, currency and promo code are checked before payment; a repeated payment is not counted twice. Each payment extends the subscription by the chosen period and lifts a suspension.

Promo codes

Discount 1–100 %, plans, validity, usage limit, single or multiple use, new users only. A 100 % code activates the subscription without payment.

Growth: trial, referrals, win-back

The “Growth” section in the menu.

  • Trial period — new bot users get N free days. Once per Telegram account and only for those who have never paid. With “after the phone number” the trial is granted when the user shares a phone number, and once per number.
  • Referrals — every user has a link like t.me/bot?start=r_ID in the bot (“Invite a friend”) and on their page. When the invited friend pays for the first time, the inviter gets the set number of days and the friend gets their own bonus if set.
  • Sources — a link t.me/bot?start=s_tag marks where a new user came from. The table shows sign-ups, paying users and revenue per tag. You can build a tagged link right on the page.
  • Win-back — N days after a subscription ends the bot sends a personal single-use discount code; it is already applied, so the user just taps “Renew with discount”. Only for users who paid before.
  • Reason for leaving — the day after a subscription ends the bot asks why the user didn't renew, with ready-made answers. Answers are shown in “Growth” and in the user card.

Telegram proxy (MTProto)

An MTProto proxy can be enabled on any server: Servers → the “MTProto” button on the server card. Set a port and a camouflage site — the proxy looks like an HTTPS site (Fake TLS), and foreign connections are passed to that site. For a server in Russia use a Russian site.

All users with an active subscription get the proxy: the “Telegram proxy” button in the bot and on the personal page. Telegram adds the proxy by itself, no VPN app is needed. Each user has their own secret; when the subscription ends, their proxy stops working. “New secrets” changes the secrets for everyone. Requires work panel 1.7.0.

Monitoring and server limits

Settings → “Monitoring”. Administrators get Telegram messages when a server has been unreachable longer than the set time and when it is back, when Xray stops, and when disk or memory use exceeds the threshold. Xray, disk and memory are checked on work panel 1.7.0.

Hoster traffic limit

Servers → “Edit”: volume in GB, period (month or day), the month start day and what to count — all traffic or outgoing only, as your hoster counts. The panel counts the server's network interface traffic. When the limit is used up, the server is removed from subscriptions until the new period, and administrators get a message. If there are no other servers, it stays in subscriptions. The counter can be reset manually.

Hiding offline servers

Settings → “Subscriptions and devices” → “Hide offline servers from the subscription”. A server disappears from the subscription if it doesn't respond for more than 3 minutes and comes back by itself. All servers are never hidden at once.

Notices and statistics

  • Notices — maintenance and news with start and end dates and an audience (everyone, active or expired subscriptions). Shown on the user page, in the bot and in apps; can be broadcast in Telegram.
  • Statistics — revenue, payments and users for a period, filters by payment method and plan, charts, CSV export.

Backups

  • Automatic — daily, weekly or monthly; the number of kept copies is configurable.
  • Manual — a full copy or selected parts: users, servers, VPN, statistics, payments, promo codes, notices, settings.
  • Restore — "Update data" (merge with current) or "Replace". The admin login, URL and path don't change; the current database is saved before restoring.
  • Backups are stored in /opt/hidevp-panel/master/data/backups/. A full copy contains node keys and tokens — keep it safe.

Updates

  • New versions are published only in GitHub releases and signed with the author's Ed25519 key. The master checks the signature and checksum; work panels check the release signature.
  • Updates → master panel — a window with a 0–100 % bar, steps and a log. The admin panel is locked while it runs. If installation fails, the previous version is restored automatically.
  • Servers — "Update to …" on each server. VPN clients stay connected.
  • Rollback — "Roll back…" for the master and "Another version…" for a server. At your own risk: the database is saved before a master rollback.
  • Without GitHub access — upload the release archive to /root and choose hidevp → "Update panel".

Settings

  • General — service name (shown in apps), public URL, support contact, default traffic and device limits.
  • Account — admin login and password. Port, secret path and domain are changed in the hidevp console.
  • Happ and INCY apps — how the subscription looks and behaves in the apps, see the section below.
  • Server camouflage — stub site, page type, title, cabinet address, hiding the work panels' API.
  • Appearance — language (Russian/English) and 4 themes, buttons at the top of the page.

Variables in names

A VPN name can contain {server}, {user}, {days}, {left}, {used}, {total}, {expire} — the panel fills in values for each user, e.g. “Netherlands · {days} days left”. Values update with the subscription.

Devices by HWID

Settings → “Subscriptions and devices”. Devices can be counted by IP (how many addresses are connected at once), by HWID (how many apps receive the subscription) or both. Happ and INCY send a HWID; when the device limit is reached, a new app gets an empty server list and a message. Users unlink old devices themselves on their page or in the bot (“My devices”), administrators in the user card. A device that hasn't refreshed the subscription for a long time is freed automatically. Reissuing links unlinks all devices.

Captions under servers

The VPN field "Caption under the name in the app" (up to 30 characters) replaces the protocol line, e.g. "For YouTube and social media". Empty — the app shows the protocol.

Provider ID for Happ

Some Happ features work only for providers with a Provider ID: captions under servers, the expiry warning with a renew button, and blocking server settings. Sign up at happ-proxy.com, copy the ID from your profile and paste it into "Happ Provider ID". INCY shows captions without it.

Security

  • The admin panel lives on a random secret path. The password is stored as a scrypt hash, sessions as SHA-256 hashes. After 5 failed attempts an IP is blocked for 10 minutes; after 50 failed attempts from all IPs, sign-in is paused for everyone.
  • Cookies are HttpOnly, SameSite=Strict and Secure over HTTPS; Origin checks, CSP, framing protection, HSTS, request size limits.
  • Site sign-in: a 6-digit code valid for 5 minutes, 5 attempts, limits per number, IP and server. The answer is the same for existing and unknown numbers.
  • Master → nodes: HTTPS with a pinned certificate and a 256-bit key; the management port is open only to the master IP.
  • Only signed updates are installed. Inputs (domains, paths, service names) are validated so they can't be injected into configurations.
  • The database, backups, keys and logs are accessible to root only.

Recommendations

  • Use a domain and HTTPS for the admin panel.
  • Sign in over SSH with a key and disable password login; change the default SSH port.
  • Keep backups off the server.
  • Update the panels and the system regularly (apt upgrade).
